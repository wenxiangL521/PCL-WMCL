# UI / 交互逻辑审计（版本选择专项）

> 触发问题：启动页“版本选择”列出了所有版本，而不是已安装版本；点击后也没有进入 PCL2 的版本选择界面。

## 已修

| # | 问题 | 处理 |
|---|---|---|
| 1 | 启动页版本选择绑定 `Versions`（全部版本） | 新增 `InstalledVersions`，只列已安装版本 |
| 2 | 没有已安装版本时，自动选中一个未安装版本 | 现在只自动选中已安装版本，否则保持未选择 |
| 3 | 启动页版本选择无法前往下载页 | 浮层内新增“前往下载页”，通过事件导航到下载页 |
| 4 | 状态栏显示全部版本数量 | 改为“共 N 个已安装版本”/“尚未安装游戏” |

## 仍未对齐 PCL2

| # | 问题 | 影响 |
|---|---|---|
| 5 | ~~“版本选择”仍是浮层~~ | 已改为独立 `VersionSelectView` 页面：左侧已安装版本、右侧详情/操作 |
| 6 | ~~版本详情只有 id/类型/时间~~ | 已补加载器、Java 运行时、实例路径 |
| 7 | ~~`LaunchViewModel` 保留 `CanInstall`~~ | 已移除 `CanInstall` 死状态；`InstallCommand` 仍用于 `--auto-install`，保留 |
| 8 | ~~`Filters`/`SelectedFilter` 死状态~~ | 已移除启动页筛选状态和无用过滤方法 |
| 9 | ~~下载页对已安装版本禁用“安装”~~ | 已允许对已安装版本重新下载/补全（仍会走安装器的跳过/SHA1 逻辑） |
| 10 | 下载页加载器仍是单独安装按钮；组合安装已改成“基础加载器 + OptiFine”组件选择 | 尚未做到 PCL2 的完整组件勾选 |
| 11 | 实例管理页仍是“列表 + 详情”双列，但已改为独立卡片、左栏固定 300px | 仍不是 PCL2 的版本子导航页 |
| 12 | Mod/整合包页仍是“列表 + 详情”双卡片 | 页面结构不同 |
| 13 | 任务按钮的进度覆盖尚未在真实任务中做视觉验证 | 只编译验证，未运行验证 |

## 结论

这确实是系统性的边界错误：启动页应只操作已安装实例，下载页才操作全部版本。本次已修正版本列表来源、无已安装时的默认选择、下载页导航、已安装版本重装入口、版本详情、死状态，并把浮层改成独立版本选择页面。剩余 4 项按上表继续处理。
