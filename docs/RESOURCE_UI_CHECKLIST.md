# 本轮需求清单与验收口径

范围：从用户提出实例资源管理、下载页复用、Mod 搜索、导出/导入整合、更新确认以及两处新闻自适应开始。下表记录当前实现，不沿用早前“已修”但只移动按钮或只改 XAML 的结论。

| 顺序 | 用户要求 | 当前实现与边界 | 验证 |
|---|---|---|---|
| 1 | 二级页不显示主导航和 PCL Logo | 原有二级页可见性绑定保留 | 既有页面导航/可见性回归 |
| 2 | Java 选择位于实例设置→设置 | 原有实例运行时下拉与路径绑定保留；不是额外添加到全局 Java 页 | 既有实例设置回归 |
| 3 | Mod/资源包/光影/存档多选与就近操作 | 多选列表保留；Mod 批量删除现在接真实集合，不再绑定单项删除；删除前一次确认 | 临时文件批量启停/删除、目标变化测试 |
| 4 | 操作条固定而非只挪到卡片上方 | Mod 操作条和搜索在 ResourceBrowserScroll 外；资源包/光影/存档工具条放管理页顶部固定区；不再以列表 MaxHeight 当作固定证据 | 实际滚动前后工具条屏幕位置保持不变 |
| 5 | 已安装 Mod 搜索 | 名称、文件名、ModId、版本详情实时过滤；清除只清关键字，不重新扫描；列表更新后同步过滤视图 | 大小写、计数、清除不扫描、刷新增量实际集合测试 |
| 6 | 底部下载复用完整下载页 | ModResourceBrowser / InstanceResourceBrowser 从原完整下载页抽取；两种入口共享同一浏览器，完整筛选/结果/详情/版本/依赖/安装/保存/分页；管理模式锁定实例和资源类型 | 假 HTTP 搜索、两个入口同实例、目标锁定、详情返回和滚动状态、多宽度回归 |
| 7 | 检查更新后选择是否更新、更新哪些 | 每个子页仅展示自身类型，独立 ResourceUpdateReviewWindow；全选/全不选/勾选、逐项反馈、失败重试、取消不自动提交 | 假更新动作与窗口真实复选框；下载哈希、陈旧文件、取消和来源不匹配测试 |
| 8 | 资源包/光影也检查更新 | 通过已安装 ZIP 的 SHA1 在 Modrinth 反查来源和当前版本，筛选相同 Minecraft 版本的兼容更新；保留原文件名与 options.txt 引用，沿既有事务校验/备份 | 假来源/下载成功、禁用名称、旧文件未变、版本兼容和未知来源回归 |
| 9 | 存档更新安全 | 不对玩家存档目录原地覆写；同类型检查页明确说明并引导在完整下载页安装新副本，未知来源不冒充可更新 | world 类型明确拒绝且零网络/零写入 |
| 10 | 导出按钮整合、解释两种用途 | 单一用途选择和导出按钮：ZIP 用于实例备份恢复；MRPACK/MCBPACK 用于分享。输出路径与扩展名按用途切换，维护工具收起，不再堆两排导出按钮 | 既有导出器 ZIP/MRPACK/MCBBS 测试与统一界面契约 |
| 11 | 导入不要独立卡片，合并到导入整合包 | 导出页没有导入区；原导入整合包入口识别 wmcl-export.json/pcl-export.json 后交 InstanceImporter；原 Modrinth/CurseForge/HMCL/Mcbbs 路径保留 | 标记优先级、重复/歧义拒绝、失败不回退、预取消及独立导入入口测试 |
| 12 | 启动页新闻自适应 | 首页保持紧凑横向图文，图片 72~112px、16:9；新闻行用满可用列宽，不再固定 300px；标题换行和 tooltip | 420/620/900/1200、多次缩放和尺寸变化、无图条目、离线新闻图像 |
| 13 | 新闻窗口自适应 | 自动计算列数、等宽占满容器，16:9 大图、标题完整换行，保留刷新/加载更多/链接校验 | 同尺寸矩阵、动态 resize、假服务刷新分页和点击（不打开浏览器） |

## 保护边界

- 没有在真实游戏目录执行删除、禁用、更新、导出或导入。行为验证使用测试目录与假 HTTP。
- Mod 批量操作增加所属目录校验和确认前后目标快照；资源批量删除同样拒绝过期目标及越界路径。资源包启用状态写入实际隔离游戏目录，不是全局根目录的 options.txt。
- 更新来源无法识别、没有兼容版本或本地文件在检查后改变时不自动替换；不会为了显示“可更新”而猜测项目。
- 目前归档资源自动检查依赖 Modrinth 文件哈希识别。没有可靠匹配的 CurseForge-only 文件或解压目录会明确显示未识别/不可自动更新，不声称全部来源都可更新。
- 存档的游玩数据优先，选择新版世界仅作为新存档安装，不替换当前游玩世界。

## 回归命令

先运行 `dotnet build WMCL.slnx -c Release`，再运行 `dotnet test WMCL.slnx -c Release --no-build --nologo`。专项包括 `InstalledModManagementFlowTests`、`ResourceBrowserReuseTests`、`ResourceUpdateReviewTests`、`ResourceArchiveUpdateFlowTests`、`UnifiedBackupImportTests` 与 `ResponsiveNewsLayoutTests`。

截图生成由 `WMCL_NEWS_SHOT_DIR`、`WMCL_RESOURCE_BROWSER_SHOT_DIR`、`WMCL_UPDATE_REVIEW_SHOT_DIR` 控制，输出到临时目录，不覆盖历史 UI 验收截图。
